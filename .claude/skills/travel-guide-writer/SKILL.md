# 旅游攻略生成与优化

一次请求完成「读偏好与订单 → 必要核验 → 排路线 → 写攻略 → 检查页面」。交付家人能照着走的攻略；不把研究报告、比价过程和候选长名单塞进执行页。生成攻略不包含订票、付款、开户或发布。

## 每次先读

1. 仓库 `README.md`、目标行程的总览与相关分页、工作区已有修改。
2. [偏好与证据](references/traveler-preferences.md)：区分明确偏好、本次条件、待确认候选。本轮指令和新订单优先，旧人数、预算、酒店或孩子年龄不是默认值。
3. [规划方法](references/planning.md)：生成或调整路线、交通、酒店时读；只改文风可跳过调研步骤。
4. [写作标准](references/writing-style.md)：写正文前读。首次使用或需要例子时读西安的「吃」与杭州的「行程」，后续不必反复读取完整历史游记。
5. [目录与显示契约](references/frontmatter-and-validation.md)：新建、移动文件及验收时读。

## 工作流

### 1. 收齐足以动手的输入

从本轮、当前文件和已确认记录提取目的地、完整日期、同行人、必做事项、已订交通住宿、预算范围、休息与行李条件。先复用已给信息；只对会改变路线或住房可行性的缺口提问，可合并成一问，并继续不依赖答案的工作。

用户只说“一键生成”时，按明确偏好推进；酒店硬底线未知就说明筛选假设，输出候选或待订动作，不能假装已有偏好或订单。日期未定保留 `wishlist`，不编班次、现价和完整日期。

### 2. 先约束，后推荐

按 [规划方法](references/planning.md) 核对已订锚点与依赖链。已有订单先保留；发现无法执行的冲突时提出影响与最小调整，不擅自取消或替换。区分订单事实、当次查证、计划估时、待确认，逐项保留来源和适用条件。

酒店先筛能否实际入住、休息、存取行李，再比较同日期同人数总成本。交通比较可行方式的门到门成本与疲劳，不默认高铁或飞机。价格、营业、票种、预约、银行等易变事实使用可用联网工具核验，官方规则优先；有 `deep-research` 时可复用其流程，不依赖指定工具才能继续。

### 3. 写一条能执行的主线

- **多城市总览**：简短概述 → `## 整体行程` → `## 出发准备` → 必要时 `## 途中提醒`。准备区只有一个标题，类目用编号，下挂 checkbox，不为每类建小标题。
- **城市页**：`## 行程` → `### YYYY-MM-DD · 当天主题` → 有序时间轴，后接 `## 吃`、`## 景点`。住宿、购物等详情仅在确有需要时保留。
- **专题页**：只写景点玩法或办事流程，链接回对应日期，不复制完整日程和全套准备清单。
- **单城市游记**：入口可合并概述、日期行程、吃、景点和一次准备清单，不为套模板硬拆文件。

从 [总览模板](assets/overview-template.md) 或 [城市模板](assets/city-template.md) 取需要的结构。示意字段必须替换或删除，没有核验的餐馆、图片、价格不填空造事实。

### 4. 改一处，回查整条链

航班／酒店／日期变化时，沿「到达 → 接驳 → 实际入住 → 睡眠 → 次日出门 → 午休 → 行李 → 下一程硬时刻」回查。人数、儿童年龄或身高变化时，回查房型、票种、早餐与乘车登记。

每个重要事实只维护一份详细记录，其他位置写必要提醒与链接。精简前后逐项对照证件、订单、午休、行李、儿童和返程动作；保留有价值的原始参考攻略与地图，不因抓取受限就删除已有来源。

### 5. 验收并交付

在仓库根运行：

```bash
node .claude/skills/travel-guide-writer/scripts/validate-guide.mjs content/trip/<trip-id>
npm run audit-content
npm run build
git diff --check
```

格式脚本只验证指定目标的默认新格式与本地链接，不能证明事实、体验或时间预算正确。用户明确要求其他版式时，说明不适用的具体格式规则，保留链接等仍适用检查，不为过门禁违背用户要求。用 [写作验收](references/writing-style.md) 检查可执行性，再按 [显示契约](references/frontmatter-and-validation.md) 打开目标 URL 检查正文、目录、时间轴、清单和链接。未完成的来源核验、页面检查如实报告；构建成功不等于已订、已上线或已由用户验收。

## 维护与回归

用户新偏好只有明确表达后才写入 [偏好与证据](references/traveler-preferences.md)，记录日期与适用场景。一次旅行和助手建议不自动成为长期偏好。纠正揭示共性问题时，更新对应规则、模板与一个 [回归场景](references/regression-cases.md)，不要只加一句口号。

修改技能后运行脚本测试、技能结构检查，并选相关场景做独立试写；回归场景不是已通过记录。本目录为该项目技能唯一来源，其他 Runtime 入口只链接这里，不复制第二份。无需新增配套 Agent。
