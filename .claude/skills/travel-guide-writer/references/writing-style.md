# 写作与内容验收

## 继承历史写法，不继承旧事实

- `content/trip/2019-xian-nanjing-hangzhou/xian.md`：吃按街区、店名、菜品组织，说明短。
- `content/trip/2019-xian-nanjing-hangzhou/hangzhou.md`：时间在前，地点与动作在后，餐饮可附菜品子列表。
- `content/trip/2022-10-02-chongqing/README.md`：具体交通与食物短评，作为亲历文风参考。

新攻略使用完整 `YYYY-MM-DD`，不继承旧篇的月日写法。历史票价、营业、个人口感与耗时不是本次事实。旧游记不因新模板被全库重写。

## 页面各自负责什么

| 页面／区域 | 负责 | 避免 |
| --- | --- | --- |
| 多城市总览 | 日期、人数、预算口径、每天一句主线、分页入口、全程准备 | 每城的小时级日程、重复状态汇总和酒店比较报告 |
| 出发准备 | 一个 h2；有序类目下嵌套 checkbox | 用 h3/h4 给每类立标题；再复制城市清单 |
| 城市行程 | 完整日期下有序时间轴，从抵达／起床到休息／离开 | 满页宽表、机械填满每小时、无依据精确分钟 |
| 吃 | 沿线街区 → 具体分店 → 菜名和一句特色 | 菜系百科、无凭据“亲测好吃”、重复地址 |
| 景点 | 玩什么、影响执行的预约／儿童条件、必要地图与来源 | 重复整段时间轴、景点百科 |
| 专题 | 复杂景点玩法、办事步骤与材料 | 第二份完整主日程、其他城市的全套准备 |

单城市入口可同时承载这些职责，不为模板拆页。专题材料只写当地流程特有内容，总览链接过去，不两边全文复制。关键时刻可为现场速查短写多次，完整订单细节只维护一份。

## 默认 Markdown 形态

```markdown
## 出发准备

1. **交通与住宿**

   - [ ] 联系已选分店，确认凌晨接待并保留前一晚房间。

2. **门票与休息**

   - [ ] 通过场馆官方入口预约本次人数和日期。
```

类目按行程实际增删。完成状态由证据决定：成人出票不等于孩子已登记；预订住宿不等于床型、早餐和延迟退房已核实。已完成项保留勾选，重排不清空用户进度，不为标“待办”复制同一项。

```markdown
## 行程

### 2026-10-02 · 西关

1. `08:00–09:00` 计划用餐时段，去已选分店吃早茶。
2. `早餐后` 沿线散步，午饭后回已订酒店午休。
```

日期后可先有一段必要说明再开始有序列表；顶层时间项以反引号开头，允许加粗时间。未来日期不确定时不用假日期触发样式。默认日程和菜品是普通列表，只有用户明确要逐项打卡时才使用 checkbox，并如实检查显示效果，不把所有列表机械变成任务。

## 写什么，删什么

- 删除“怎么选／值不值得／推荐逻辑／逐晚落脚逻辑”等研究段，保留选定的地点、动作与必要条件。正在选酒店时可单独答比较问题，选定后的执行页不继续带着淘汰表。
- 不展开第二套完整路线；受影响步骤旁写一句“遇到 X，执行 Y”。Y 必须能执行，有待订车票或房间时一起标出。
- “核对信息”改为具体对象、渠道与结果，例如“联系所选分店，确认当天午餐订位、地址、儿童椅和收费”。
- 精简不删适用的证件、预约、漫游、现金、入境小票、雨衣、寄存取箱、儿童权益与返程接站。搬到别页后必须有可达链接。
- 店名含具体分店，地址只写一次，菜名后一句客观特色。未经亲历不写“我吃过”“一般”“必吃”；未知餐馆先写沿线区域待定，不虚构完整名单。
- 硬时刻按订单／官方规则，计划时段明确是安排，交通余量写“预留”。查询价注明日期、人数、币种与权益；已付价保持订单口径。
- 来源在事实旁简短可点击；原始攻略、地图有价值就保留。来源列表不能替代正文事实的对应关系，也不用公开搜索词和工具过程。
- 界面与正文直接呈现城市、日期、动作，不加“行程分页”“本页用于”“以下内容展示”等描述容器或实现的空话。导航已有实际条目时，不再重复一个泛化标题；无障碍名称可以保留在语义属性中。

## 内容验收

每次生成或改写人工检查；格式脚本不能代替这些判断。

- [ ] 所有硬约束和已订订单保留；候选、计划、查证、完成状态分明。
- [ ] 日期连续性、天数晚数、入住退房覆盖成立；跨午夜到店没有丢掉前一晚。
- [ ] 起落点、换乘、等候、步行、边检、停检、取行李、吃饭、睡眠都计入时间；不存在同一人同时办事与陪娃。
- [ ] 本次需要床上午睡时，午休地点有真实可用床铺和时段；待落实时有具体动作与可执行退路。
- [ ] 酒店是最新完整分店；没有把旧候选床型、窗型、早餐或取消政策继承给新订单。
- [ ] 总览、城市、专题和元数据一致；必要动作与原始来源能从新位置找到。
- [ ] 一条主线，吃与景点简短；删的是冗余和过程，不是执行条件。
- [ ] 明确偏好与本次条件分离，未把一次选择写成永久偏好。
- [ ] 用 [显示契约](frontmatter-and-validation.md) 验证实际页面；未执行检查如实说明。

改技能时用 [回归场景](regression-cases.md) 做独立试写，失败后修对应规则和模板，不能仅在最终报告解释错误。
