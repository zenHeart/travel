# 写作与内容验收

## 继承历史写法，不继承旧事实

- `content/trip/2019-xian-nanjing-hangzhou/xian.md`：吃按街区、店名、菜品组织，说明短。
- `content/trip/2019-xian-nanjing-hangzhou/hangzhou.md`：时间在前，地点与动作在后，餐饮可附菜品子列表。
- `content/trip/2022-10-02-chongqing/README.md`：具体交通与食物短评，作为亲历文风参考。

新攻略使用完整 `YYYY-MM-DD`，不继承旧篇的月日写法。历史票价、营业、个人口感与耗时不是本次事实。旧游记不因新模板被全库重写。

## 页面各自负责什么

| 页面／区域 | 负责 | 避免 |
| --- | --- | --- |
| 多城市总览 | 日期、人数、每天一句主线、分页入口；按序仅有整体行程、出发准备、成本三个 h2 | 第四个总览区块、每城的小时级日程、固定预算声明和酒店比较报告 |
| 出发准备 | 一个 h2；“未完成／已完成”有序类目下嵌套带主题 Tag 的 checkbox，未完成跨主题按重要程度从高到低 | 按证件、交通等主题再拆组；用 h3/h4 给类目立标题；用常识提醒充待办；再复制城市清单 |
| 成本 | 用户已给的订单总价、币种、覆盖权益、已提供金额小计 | 清单重复账单、未知当零、把部分金额叫作全程总成本 |
| 城市行程 | 完整日期下有序时间轴，从抵达／起床到休息／离开 | 满页宽表、机械填满每小时、无依据精确分钟 |
| 吃 | 沿线街区 → 具体分店 → 菜名和一句特色 | 菜系百科、无凭据“亲测好吃”、重复地址 |
| 景点 | 玩什么、影响执行的预约／儿童条件、必要地图与来源 | 重复整段时间轴、景点百科 |
| 专题 | 复杂景点玩法、办事步骤与材料 | 第二份完整主日程、其他城市的全套准备 |

单城市入口可同时承载这些职责，不为模板拆页。专题材料只写当地流程特有内容，总览链接过去，不两边全文复制。关键时刻可为现场速查短写多次；订单金额与覆盖权益的详细记录集中在成本区，执行时必要的时间和条件留在相关日程。删掉的日常提醒不整批移入备注；只把影响本次执行的特有信息留在对应日程，不另起总览 h2。

## 成本口径

- 只汇总用户已给出的订单总价，注明币种及对应日期、人数／房晚、套餐范围；不拿网上现价补成已订金额。缺金额写“未提供”或“待确认”，不填 0。
- 用户明确餐饮等费用稍后补充时，保留“未提供”，不为补齐成本追问，不自行估算填数字。
- 只对有金额的当前订单求“已提供金额小计”，说明尚未包含的项目；没有完整金额时不称“全程总成本”，不自动补预算上限。
- 用户已给出的预估单列并标“预估”，不混进已订小计。退款金额、到账状态和手续费分列；已取消订单退出当前已订小计，未知手续费保持待确认，不将原订单金额与手续费重复记作支出。
- 不同币种分别小计。确需折算时注明用户提供或当次核验的汇率和日期，原币金额与折算值是同一笔费用，不重复相加；没有汇率依据不算跨币种总计。
- 套餐只按订单总价计一次，包含的住宿、门票和早餐不再拆开累计；只有确认另外付费的项目才另记。押金、换现金和账户周转金不作为消费。
- 清单保留“已订／已出票”等完成状态及符合下方准入标准的未办动作；金额移到成本区后不清空已完成勾选，也不复制完整账单。

## 待办准入与完成证据

每个未完成项须同时满足三项，不能只把提醒换成“落实／确认／办理”等动词：

1. **有未落实证据**：用户明确尚未购买或办理、订单显示必要登记未提交，或已确认约束暴露实际缺口。文档没写、资料未知、助手没见凭据，不等于用户没办。
2. **有具体办理结果**：例如订妥仍缺的一晚酒店、买到已确定行程的票、完成必要预约或登记。只装好物品、保存截图、核对信息或执行日常操作，不构成本清单要追踪的结果。
3. **本次确有必要**：不完成会阻碍已选择的行程或用户明确要办的事项；不能因模板有此项、可能有帮助或需要补齐资料就加入。

- 装证件／行李、保存订单或截图、值机／托运、开关漫游、备现金、App 安装测试、常规机场接送与返程接站提醒不默认列为待办；常识、策略、应急号码和泛泛保障核对同样删除。确有未订酒店、未买行程票或必要预约／办理时，保留相应结果，不用这些日常步骤替代。
- 已订酒店不因床型、早餐或晚到信息未写全而生成一组复核待办。商家明确尚未回复且该答复妨碍实际入住时，才保留具体阻塞，例如“酒店尚未答复凌晨能否接待，取得可入住确认”。未知权益在订单说明中保持未知。
- 现场办卡等操作步骤放专题。若用户明确本次要办且尚未办，可在总览保留对应办理结果并链接专题；不把装 App、测试网络或保存材料逐条拆成总览任务。
- 用户明确确认、订单凭据以及用户维护的本地 `- [x]`／`- [X]` 都是相应事项的完成证据。整理时可统一为 `[x]`，不得因换组或改写而清空；只保留原勾选范围，不扩展为其他同行人的事项已完成。日期已过、预计已经发生，均不是完成证据。
- 删除无意义待办后，不把它们换成一长段备注。只有影响执行的特有条件，例如特殊入场材料或指定取箱截止时间，才在对应日程或专题保留；不再制作另一份常规准备清单。

## 默认 Markdown 形态

```markdown
## 出发准备

1. **未完成**

   - [ ] <span class="task-tag">住宿</span> 预订本次仍未订房的一晚，写明已确定日期和入住人数。
   - [ ] <span class="task-tag">预约</span> 完成本次已选场馆所需且尚未完成的预约，写明日期与人数。

2. **已完成**

   - [x] <span class="task-tag">交通</span> 成人交通已出票。
```

准备区仅有“未完成”和“已完成”两个有序类目，下挂 checkbox；可省略空类目并连续编号，未完成始终在已完成前。先按准入标准筛选，再将所有未完成事项按本次硬约束的重要程度从高到低排列，不能再拆证件、交通、办卡等主题类目。重要程度由人工结合截止时间、对出行的影响和用户要求判断，不固定所有行程的事项顺序，也不为凑主题添任务。

两种状态都没有事项时，在准备区写普通文本“暂无准备事项”，不为填模板造任务。

目标多城市总览每项 checkbox 开头使用 `<span class="task-tag">交通</span>` 形式的主题 Tag，文字按事项取证件、交通、住宿等实际主题；Tag 只作展示，不筛选、不点击，不据此重新分组。历史游记及专题不强制添加。

示例必须替换为本次有依据的事项，不适用就删除。已完成项统一放入“已完成”，重排不清空用户进度。同一条若混合已完成事实与有证据未落实的必要动作，应拆清状态；成人已出票不代表孩子已登记，但仅仅没看到孩子的登记资料也不能自动造核对待办。

出发准备不自动加入 Gucci 等品牌购物、款号、询价或留货待办；确有购物安排时放在城市页「购物」，只有用户明确要求才列入准备清单。删除清单项时同步修正指向该项的文案与链接。

```markdown
## 行程

### 2026-10-02 · 西关

1. `08:00–09:00` 计划用餐时段，去已选分店吃早茶。
2. `早餐后` 沿线散步，午饭后回已订酒店午休。
```

日期后可先有一段必要说明再开始有序列表；顶层时间项以反引号开头，允许加粗时间。未来日期不确定时不用假日期触发样式。默认日程、菜品和专题普通步骤使用普通列表，专题操作顺序可用编号；只有用户明确要逐项打卡时才使用 checkbox，并如实检查显示效果，不把所有列表机械变成任务。

## 写什么，删什么

- 删除“怎么选／值不值得／推荐逻辑／逐晚落脚逻辑”等研究段，以及“沿用已确认信息、具体权益以订单为准”等过程说明。删除被用户撤回的预算声明，不将旧金额填成固定预算；保留选定的地点、动作与必要条件。正在选酒店时可单独答比较问题，选定后的执行页不继续带着淘汰表。
- 不展开第二套完整路线；受影响步骤旁写一句“遇到 X，执行 Y”。Y 必须能执行，有待订车票或房间时一起标出。
- 先判断“核对信息”是否满足待办准入标准；不满足就删除，不能只补上对象、渠道和细节使它看似具体。已确认的真实阻塞才写需取得的办理结果。
- 待购车票保留用户已给的具体日期、车次、出发与到达时刻，缺项标“待补”；不把明确班次压缩成“买往返票”，不补造未知字段，也不把待购写成已出票。
- 用户明确取消的安排从日程和待办中移除，并核对成本与链接；有真实已付订单时仍按退款口径处理，未订安排不保留虚构费用。不按旧的午休需求自动补回已取消的午休房或延迟退房，也不推断以后不午休。
- 精简保留已订事实、适用硬时刻、必要预约／办理及执行特有条件；常规物品和操作不作为必留清单。需要移到日程或专题的特有信息保留可达链接，不将删项整批搬家。
- 店名含具体分店，地址只写一次，菜名后一句客观特色。未经亲历不写“我吃过”“一般”“必吃”；未知餐馆先写沿线区域待定，不虚构完整名单。
- 硬时刻按订单／官方规则，计划时段明确是安排，交通余量写“预留”。查询价注明日期、人数、币种与权益；已付价保持订单口径。
- 来源在事实旁简短可点击；原始攻略、地图有价值就保留。来源列表不能替代正文事实的对应关系，也不用公开搜索词和工具过程。
- 界面与正文直接呈现城市、日期、动作，不加“行程分页”“本页用于”“以下内容展示”等描述容器或实现的空话。导航已有实际条目时，不再重复一个泛化标题；无障碍名称可以保留在语义属性中。

## 内容验收

每次生成或改写人工检查；格式脚本不能代替这些判断。

- [ ] 所有硬约束和已订订单保留；候选、计划、查证、完成状态分明。
- [ ] 多城市总览按序只有整体行程、出发准备、成本三个 h2；只在对应日程保留执行特有信息，未将删项堆成备注或用过程说明充当正文。
- [ ] 出发准备仅用“未完成／已完成”有序类目并嵌套带主题 Tag 的 checkbox，省略空类目，未完成在前、已完成正确 `[x]` 后置；未完成动作跨主题按本次重要程度从高到低，经人工检查而非脚本代判。
- [ ] 每个未完成项都有未落实证据、具体购买／预约／登记等结果和本次必要性；没有仅因资料未知生成的核对，也没有装证件行李、保存订单、值机托运、漫游现金、App 安装测试、常规接送或泛泛酒店复核。
- [ ] 用户本地 `[x]`／`[X]` 完成证据得到保留，未因日期已过猜测完成，未将已完成拆成新的核对任务；现场办卡步骤仍在专题。
- [ ] 成本仅用用户已给订单金额；未知、预估、退款手续费与已订金额区分，套餐与币种未双算，押金和换现金未计消费，清单未重复账单或丢失完成状态。
- [ ] 待购交通未丢用户给出的日期、车次和时刻，缺项保持待补；用户明确后补的费用未被追问或自行估算。
- [ ] 日期连续性、天数晚数、入住退房覆盖成立；跨午夜到店没有丢掉前一晚。
- [ ] 起落点、换乘、等候、步行、边检、停检、取行李、吃饭、睡眠都计入时间；不存在同一人同时办事与陪娃。
- [ ] 本次需要床上午睡时，午休地点有真实可用床铺和时段；待落实时有具体动作与可执行退路。
- [ ] 显式取消已同步到日程、待办、成本与相关链接，没有自动补回，也未误删其他日期仍适用的休息安排。
- [ ] 酒店是最新完整分店；没有把旧候选床型、窗型、早餐或取消政策继承给新订单。
- [ ] 总览、城市、专题和元数据一致；必要动作与原始来源能从新位置找到。
- [ ] 一条主线，吃与景点简短；删的是冗余和过程，不是执行条件。
- [ ] 明确偏好与本次条件分离，未把一次选择写成永久偏好。
- [ ] 用 [显示契约](frontmatter-and-validation.md) 验证实际页面；未执行检查如实说明。

改技能时用 [回归场景](regression-cases.md) 做独立试写，失败后修对应规则和模板，不能仅在最终报告解释错误。
