# 攻略技能行为回归

这些是测试输入与判定标准，不是已通过记录。修改对应规则后，挑相关场景交给独立 Agent，提供技能路径、原始资料、输出目录和权限边界，不先喂预期答案。观察实际产物，再按本表评分。

使用 Git 忽略的任务目录保存测试产物，事实用明确的测试资料；不改真实订单、不联网下单、不污染 content/trip。不把生成输出加入偏好证据。没有完整运行的场景保持“未执行”。

## 判定与边界

- **阻塞**：已订事实丢失／覆盖、未知被写成确认、不可执行的时间／床铺、偏好误继承、链接断裂、必要动作被删除。
- **需修**：输出结构回退、研究过程重新进正文、手机表格挤压、重要来源丢失。
- **通过**：相关阻塞与需修项均消除，输出可读且检查范围明确；脚本绿灯不替代事实和页面验证。

准备区名称、顺序、对应 checkbox 状态与 Tag 结构可由确定性脚本检查；是否真实未办、重要程度排序、用户已给车次是否完整保留、显式取消是否正确联动，以及费用后补是否被尊重，都须独立试写后人工判定。未实际执行的场景保持“未执行”，不能把新增场景当成通过证据。

## 根因与规则的对应

过去几轮改写中，SKILL 和模板仍要求月日、城市准备小标题及全面 checkbox，和新版页面目标冲突；仅改正文后下一次会被旧模板带回去。现将结构同时更新到入口、模板与格式检查。

Git `4098fb1` 到 `dd344d3` 及本次工作区显示：简洁文风规则已经存在，酒店选择论证仍再次进入执行页；旧分店的路线和权益也容易沿用。现明确“比较阶段／执行阶段”、订单优先级和修改影响链，不能只重复“去冗余”。

酒店、午休和行李安排曾只散落在单次攻略；直接抽成永久偏好会误伤下一次旅行。现分为明确偏好、当次约束、可覆盖建议，测试成人独行与新同行人以检查污染。

2026-09-25 用户最终将准备清单澄清为两个状态类目，主题改用 Tag，未完成跨主题按重要程度排序；早先的主题分组规则由此被替换。同步约束真实未办动作、已给交通字段、显式取消及费用后补，避免后续生成又恢复旧分组或补回已取消安排。
