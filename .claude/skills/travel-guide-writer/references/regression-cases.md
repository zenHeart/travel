# 攻略技能行为回归

这些是测试输入与判定标准，不是已通过记录。修改对应规则后，挑相关场景交给独立 Agent，提供技能路径、原始资料、输出目录和权限边界，不先喂预期答案。观察实际产物，再按本表评分。

使用 Git 忽略的任务目录保存测试产物，事实用明确的测试资料；不改真实订单、不联网下单、不污染 content/trip。不把生成输出加入偏好证据。没有完整运行的场景保持“未执行”。

## 真实弱点与场景

| 场景输入 | 必须观察到 | 失败表现 |
| --- | --- | --- |
| “按我的偏好一键生成下一次攻略”，仅给新日期、两名成人、目的地 | 使用写作偏好，重新收集影响可行性的输入；不复制上次孩子、预算、箱数或办卡 | 自动变成两大一小／固定午睡／固定金额 |

| 23:50 落地、凌晨到店，次日原计划早起 | 保留正确房晚、晚到确认动作，检查睡眠并减活动 | 把到店日期当入住日；机械套次日七点出门 |

| 成人票已购、孩子登记未知；酒店仅有总价 | 成人完成状态保留，孩子登记和房型权益保持待确认 | 自动把所有 checkbox 勾上，虚构早餐／床型 |

| “按西安短评写新餐馆” | 学短句结构，店和菜来源可追溯，没有虚假体验 | 用旧“我吃过／好吃”或旧价格冒充本次 |
| “出发准备一个标题，下级是序号” | 一个 h2、编号类目、嵌套 checkbox，旧类目锚点更新 | 六个 h3 继续进目录；数目写死为六类 |

| 用户给出消费订单、酒店押金和换现金金额，要求补成本 | 成本仅累计消费订单；押金、现金兑换和周转金不作为消费 | 直接累加全部金额，或把部分订单小计写成全程总成本 |
| 行程有 Gucci 购物，要求准备清单去掉此类描述 | 清单移除品牌购物待办及空类目；城市购物信息保留，旧清单引用修正 | 换成泛称购物继续塞清单，或误删城市购物安排、推断用户排斥品牌 |
| “去掉行程分页这种无意义描述” | 桌面直接显示导航条目，移动入口显示当前内容，语义名称仍可读 | 换一个空泛标签继续占一行；删除标签后折叠入口不可识别 |
| 新完整日期城市页与专题 | 城市显示时间轴，专题保留特有步骤、不复制日程 | 模板仍是 MM.DD 或宽表，专题重复一日安排 |
| 成人独行、未知日期、境外超出地图范围 | 不强制亲子午睡，不编日期或坐标，说明实际站点限制 | 套用儿童权益或填假坐标过校验 |

## 判定与边界

- **阻塞**：已订事实丢失／覆盖、未知被写成确认、不可执行的时间／床铺、偏好误继承、链接断裂、必要动作被删除。
- **需修**：输出结构回退、研究过程重新进正文、手机表格挤压、重要来源丢失。
- **通过**：相关阻塞与需修项均消除，输出可读且检查范围明确；脚本绿灯不替代事实和页面验证。

## 根因与规则的对应

过去几轮改写中，SKILL 和模板仍要求月日、城市准备小标题及全面 checkbox，和新版页面目标冲突；仅改正文后下一次会被旧模板带回去。现将结构同时更新到入口、模板与格式检查。

Git `4098fb1` 到 `dd344d3` 及本次工作区显示：简洁文风规则已经存在，酒店选择论证仍再次进入执行页；旧分店的路线和权益也容易沿用。现明确“比较阶段／执行阶段”、订单优先级和修改影响链，不能只重复“去冗余”。

酒店、午休和行李安排曾只散落在单次攻略；直接抽成永久偏好会误伤下一次旅行。现分为明确偏好、当次约束、可覆盖建议，测试成人独行与新同行人以检查污染。
