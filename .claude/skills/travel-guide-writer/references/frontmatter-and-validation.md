# frontmatter 契约与校验规则

来源：`scripts/audit-content.js`（`npm run audit-content` 跑的就是这个脚本）。这里把脚本里的规则翻译成写作时的检查清单；规则本身以脚本为准，脚本改了这份文档要跟着改。

## index.md 必须满足

```yaml
---
chinese_name: 香港        # 必填
english_name: Hong Kong  # 必填
coordinates: [114.1694, 22.3193]   # 必填，[经度, 纬度] 二元组
tags: []
date: 2026-09-25
layout: blog
---
```

- `chinese_name`、`english_name` 缺一个都是 ERR。
- `coordinates` 必须是长度为 2 的数组；经度要落在 73—136，纬度落在 3—54（中国大致范围），越界报 ERR。
- 同一坐标不能被两个 `chinese_name` 共用（会在地图上重叠成一个点）——新城市选坐标前，搜一下仓库里有没有别的城市/子页已经用了同一对经纬度。
- 同一个 `city-id` 目录名不能同时出现在 `visited`、`planned`、`wishlist` 里两个状态下——迁移城市状态时要把旧状态目录删掉或改名，不是复制一份。

## 子页（非 index.md）frontmatter

子页可以完全不写 frontmatter。但只要写了 `coordinates`，就必须同时写 `chinese_name`，否则这个坐标不会在地图上生成点位（ERR：写了等于没写，白白留一个不生效的字段）。

常用字段：

```yaml
---
order: 3          # 决定在导航里的排序，越小越靠前；不写的排到最后，按文件名排
nav_title: 27—29日 深圳与过关   # 导航里显示的短标签；不写就退回 chinese_name，再退回正文第一个一级标题
chinese_name: 福田口岸   # 只有需要在地图上单独成点时才需要
coordinates: [114.0703, 22.5147]
---
```

`order` 的编号习惯（参照 `hongkong/` 现有用法）：按行程日期顺序从小到大编号；已取消/延后、不属于本次主线的子页用 90+（如 `disneyland.md: 91`、`lantau.md: 92`），排到导航最后，不占正常行程的排序位。

## 站内链接与图片

- 正文里 `[文字](./other.md)` 这种相对链接，脚本会检查目标文件是否真的存在——改名或删除子页后，记得全仓 `grep` 一遍旧文件名，把指向它的链接改掉或删掉。
- `![](./xxx.jpg)` 同理检查文件是否存在；即便存在，脚本还会提醒图片是否已经复制到 `public/content/` 对应路径下（线上构建只认 `public/` 里的文件，`content/` 里放着但没同步到 `public/` 会导致线上 404，这是 WARN 不是 ERR，但别忽略）。

## 正文长度与标题

- 去掉 frontmatter 后正文少于 40 字符会被判定"内容过短"（WARN）——纯占位的空子页不要留在仓库里，要么写满，要么先别建这个文件。
- 正文必须有至少一个一级标题 `# 标题`（WARN：没有的话 tab 名会退化成文件名）。

## 编号引用 `[n]` 的一致性（只用于专门的调研/比价页）

如果正文里出现 `[1]` `[2]` 这类编号引用，脚本会要求文件里必须有一个 `## 参考来源` 小节，并且：

- 正文用到的每个编号，`## 参考来源` 下必须有对应的 `1. ...` 列表项。
- 每条来源必须包含一个可点击链接（`](http...)` 或 `](./...)`），纯文字来源不算。
- 反过来，`## 参考来源` 里定义了但正文没用到的编号会报 WARN（多余引用，删掉或者把正文里对应那句话补上编号）。

这套编号引用体系只用在类似 `transport-value.md` 这种"调研+比价"页面上；日常执行页（当天时间轴、预算表）直接把官方链接写进正文，不需要建这套编号系统。

## 中文加粗渲染坑（容易踩，务必注意）

CommonMark 判断 `**粗体**` 合不合法，依赖左右两侧字符是不是"punctuation"，而中文全角标点（，。、；：！？） 」』】》）也算 punctuation。这导致：

```
改期**，不保证**      ← 错：** 紧跟在中文逗号「，」后面，起始 ** 不构成合法开标记，
                         会原样输出两个星号，而不是渲染成粗体
```

正确写法是把 `**` 移到标点之后：

```
改期，**不保证**      ← 对
```

同理，加粗内容以中文标点开头或以左括号 `（「『【《(` 结尾，也会被脚本标成 WARN（提示"** 应移到标点之后/括号之前"）。写完粗体句子，习惯性检查一下 `**` 两侧贴的是不是中文标点。

## 写完必须跑

```bash
npm run audit-content
```

看到 `✓ 内容层无问题` 才算完工。有 ERR 必须改到没有；WARN 能顺手改就改，不能改要能说清楚为什么保留（比如图片确实还没准备好复制到 `public/`）。
