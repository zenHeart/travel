# 目录、frontmatter 与校验

以仓库 `README.md`、`scripts/audit-content.js`、`src/utils/tripScanner.ts` 和页面渲染实现为准；本文件是写作速查。结构变更前读对应实现，不沿用旧版城市目录规则。

## 行程与分页

```text
content/trip/<trip-id>/
├── README.md              # type: trip，总览或单城市全文
├── zhuhai.md              # type: city，城市行程与地图点位
├── zhuhai/
│   └── chimelong.md        # type: note，长隆玩法
├── hongkong.md            # type: city
└── hongkong/
    └── banking.md         # type: note，办卡流程
```

- 入口 `README.md` 必填 `type: trip`、`title`、`status`；状态为 `visited`、`planned`、`wishlist` 之一。
- 日期确认时用 `start_date: "YYYY-MM-DD"`；仅知道年份用 `start_year`，不把提交日期冒充出行日期。
- 单城市入口可加 `chinese_name`、`coordinates` 生成地图点位。
- 城市页必填 `type: city`、`chinese_name`、`coordinates`；常用 `order` 控制排序、`nav_title` 控制导航短名。
- 详情页使用 `type: note`，设置 `nav_title`、`order`；详情页不生成地图点位。
- 每个嵌套页必须存在同名路径的父页面，例如 `hongkong/banking.md` 的父页面是 `hongkong.md`。导航根据路径显示层级。
- `coordinates` 为 `[经度, 纬度]` 数值数组；当前审计要求经度 73–136、纬度 3–54。超出范围的旅行需要先处理站点契约，不能填假坐标。
- 同一城市可出现在不同次历史行程；不要为去重而删除原始游记。

常驻地使用 `content/place/<place-id>/README.md`，必填 `type: place`、`chinese_name` 与坐标；不混入行程时间轴。

## 链接、页面路径与图片

- 总览到城市页：`[香港](./hongkong.md)`。
- 城市到详情：`[办卡](./hongkong/banking.md)`。
- 详情返回父页：`[香港](../hongkong.md)`。
- 网页路由：`#/<trip-id>/index`、`#/<trip-id>/hongkong`、`#/<trip-id>/hongkong/banking`。
- 移动或改名时用 `rg` 搜旧路径并修复所有受影响链接；站内链接仍引用真实 `.md` 文件。
- 图片放对应游记目录，以 `./` 或 `../` 相对引用。生产路径在 `public/content/`，按项目资源同步机制处理，实际打开确认无 404。

## Markdown 与 checkbox

- 每页有一个一级标题，正文不要空占位。
- 多城市总览按序只有 `## 整体行程`、`## 出发准备`、`## 成本` 三个 h2；常识、策略与日常操作不充待办，也不将删项整批搬入备注，只有本次执行特有信息留在对应日程。单城市入口合并城市正文时保留行程、吃与景点等必要结构。
- 待办使用 `- [ ]`；用户确认、订单凭据及用户本地勾选的 `- [x]`／`- [X]` 都是相应事项的完成证据。整理时可统一为 `[x]`，不得清空或扩大完成范围；日期已过不是完成证据。站点已有 checkbox 点击与本地保存功能，无需为一次内容改写增加状态代码。
- 新城市页用 `### YYYY-MM-DD · 当天主题`，日期下有序列表各项以反引号时间开头（可加粗），与当前时间轴渲染契约一致。可以先有说明段，时间可用“早餐后”等真实相对时段；不编分钟。
- 总览的 `## 出发准备` 下仅用“未完成／已完成”有序类目嵌套 checkbox，不用 h3/h4；省略空类目并连续编号，未完成在前、已完成置后。未完成组只能用 `- [ ]`，已完成组只能用 `- [x]`，不按主题再拆组。未完成的真实动作跨主题按本次重要程度从高到低，是否真实未办及重要程度须人工判断。
- 两种状态都没有事项时，准备区可写普通文本“暂无准备事项”，不保留空类目或虚构任务。
- 目标多城市总览每项 checkbox 开头用 `<span class="task-tag">交通</span>` 标注实际主题，Tag 只展示、不交互，不使用新语法或按 Tag 分组。历史游记及专题不强制加 Tag。
- 成本使用紧凑列表或短表，金额与权益只在这里详细维护；准备清单保留完成状态和动作。金额及小计按 [成本口径](writing-style.md#成本口径) 人工核对，格式校验不能证明金额完整或正确。
- 美食按街区、门店和菜名列表组织。日程默认不用表格；短字段确需对照时才保留表格，来源直接链接事实，不拿宽表包装整段叙述。
- 加粗内容遇中文标点可能渲染成字面星号。写作时避免 `**店名（分店）**吃饭`，改为 `**店名（分店）** 吃饭`，并运行审计检查真实 Markdown 解析。
- 普通攻略在事实旁直接链接来源；总览不为来源增加第四个 h2。其他页面若用数字编号来源 `[1]`，需有 `## 参考来源` 和对应带链接编号项。

## 交付验证

```bash
node .claude/skills/travel-guide-writer/scripts/validate-guide.mjs content/trip/<trip-id>
npm run audit-content
npm run build
git diff --check
```

`validate-guide.mjs` 只检查显式指定的行程或单文件，覆盖新格式、真实日历日期、编号时间轴、多城市总览的三个 h2 及其顺序、总览清单、相对文档与锚点、本地图片；清单验证“未完成／已完成”名称、顺序、对应完成标记及目标多城市总览每项的 Tag 结构，不判断重要程度或是否真实未办。不强制历史游记重写，不把未定日期变成编造的日期。链接锚点复用 `src/utils/toc.ts`，本网站只有 h2/h3 进入目录并获得该锚点，不能假定 h4 店名可跳转。

`audit-content` 是全仓库旧契约检查，覆盖 frontmatter、父页面、链接、图片、引用和加粗等。两个脚本都不核验外部价格、交通可行性或文风，另按 [写作验收](writing-style.md) 检查。

## 实际页面验收

用户给 URL 时检查该 URL；新建时打开对应本地路由，不只报告文件存在。普通内容修改至少在手机窄屏与桌面各看一次；涉及布局或长表时再检查平板和大屏。

- 多城市总览目录按序只有整体行程、出发准备、成本；没有准备类目或备注挤进目录。准备区仅有非空的未完成、已完成有序类目，状态准确；Tag 显示为小标签且没有按钮或筛选交互。成本短表在窄屏可读，未知金额及小计范围清楚。
- 逐项按 [待办准入与完成证据](writing-style.md#待办准入与完成证据) 人工检查未落实证据、具体办理结果及本次必要性，再跨主题按重要程度排序。资料未知未被自动转成核对，已订酒店没有泛复核；有明确未答复且影响入住的真实阻塞仍保留。待购交通保留已给日期、车次与时刻，取消安排未被补回，费用后补未被追问或自行填数字。
- 用户本地完成标记未被重排或改写抹除，日期已过未被当作完成依据；常规物品、保存截图、值机托运、漫游现金、App 安装测试及接送没有换成泛具体任务或一大段备注，办卡操作步骤仍在专题。
- 可见界面没有“行程分页”等只描述容器的冗余标签；桌面直接展示导航条目，移动端折叠入口显示当前内容，保留必要无障碍命名。
- 城市有一个 h1、完整日期标题、有序时间轴，后接吃和景点；没有字面星号、占位字段或重复整章。
- 375px 左右窄屏正文不横向溢出，表格需要时只在自身区域滚动，文本不是一字一行；桌面有合理正文宽度。
- 可点击导航、按钮、checkbox 有正确光标、焦点与足够点击范围；图片确实有预览时才呈可点击样式。内容改写发现组件问题时做必要的小修，不为写一篇攻略重建组件系统。
- 父子页、跨页日期和准备区链接实际可跳转；标题改名或类目从 h3 变列表时同步修旧锚点。
- 本地图片加载成功；有预览时验证打开与关闭。不要为装饰增加未知来源图片。
- 若涉及清单重排或状态代码，验证勾选、刷新、换页与重排后的保存，测试后恢复原状态。日常只改文案不反复改用户真实勾选。

没运行的步骤如实报告，不把静态检查当自动发现、Runtime 热加载、线上发布或人工验收证明。
